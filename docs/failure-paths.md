# 新しい実装で必ず満たす失敗経路

旧実装（`b5e0e8d`）のレビューで見つかった失敗経路の一覧。作り直しを指示した前のスレッドが、新しい実装で必ず満たす要件として決めた。ユーザーの言葉ではない。旧実装のコードは参照も流用もしない。

それぞれ、HTTPかワーカー単位のテストで確かめる。

- 帳票1件の例外やタイムアウトの後も、後続のジョブが処理される。
- 再起動・停止・DB障害で、ジョブが消えない、重複しない、止まったままにならない。まだClaudeへ送っていないジョブを、再起動で失敗扱いにしない。
- 認証のない要求に、アップロードの受付枠やメモリを使わせない（healthなどのパスも含む）。
- Claudeの応答を受け取った後にDBへの記録が失敗しても、課金済みの結果を捨てない。
- 受付処理（ファイル保存とDB登録）でイベントループを止めない。要求がキャンセルされても、登録済みジョブのファイルを消さない。
- 変換の子プロセスは、時間を超えたら確実に終了させる。Windowsでvenvの `python.exe` が中継役になる場合の孫プロセスと、サービスを強制終了したときの残留にも備える（子プロセス自身にも制限時間を持たせる、など）。
- 起動の失敗（ポート使用中、多重起動）をログに必ず残す。APIキー・ファイル名・帳票本文はログに出さない。
- 透過画像は、白い背景に合成してから変換する。
- 金額も明細も持たないテスト専用タスクが、基盤のコードを変えずにHTTP経由で受付から取得まで通る。
