# Claude API 社内共通基盤 構築方針

## 目的

請求書・納品書・発注書などのAI読み取りを共通化し、PAD・その他社内システムから利用できるREST APIを構築する。
Claude APIは読み取り・情報抽出を担当し、前処理・検証・業務登録は別途実装する。

## 技術構成

* Python 3.14 / FastAPI / Anthropic SDK / Pydantic
* 既存LossyのWindowsサーバーに独立サービスとして配置（例：Port 8001）
* LossyとはPython環境・プロセス・設定・ログを分離
* Claude APIへの接続処理は共通化
* 帳票・処理目的ごとにプロンプト、JSONスキーマ、検証処理を切り替える
* モデル変更や帳票追加に対応できる設計

## 処理フロー

1. REST APIでPDF・画像とタスクIDを受信
2. PDF画像化・回転補正などの前処理
3. タスク別プロンプト・スキーマでClaude APIを実行
4. Pydanticによる構造検証、不明項目はnull
5. 結果を統一JSONで返却（成功・要確認・失敗）
6. 呼び出し元で業務固有の照合・登録を実施

## API設計

* POST /api/v1/documents/extract
* タスク例：invoice.extract、delivery.extract、purchase_order.extract
* レスポンス：処理ID・ステータス・抽出データ・エラー情報
* 長時間処理に備え、ジョブIDによる非同期処理も考慮
* PADから直接利用できる標準的なHTTPインターフェース

## 共通基盤の管理機能

* API認証・アクセス制御
* タイムアウト・リトライ・同時実行数制限
* 処理履歴・エラーログ・トークン使用量・コスト記録
* プロンプト・モデルのバージョン管理
* 重複処理防止・再実行への対応
* APIキーの安全な管理、機密情報のログ出力抑制

## 初期開発範囲・留意点

* まず請求書・納品書の2種類に対応
* PADとPythonからの直接API利用を優先
* クラウド版Power Automate連携は後回し（ゲートウェイ・ライセンス等の検討が必要）
* 初期は同時帳票処理1件に制限
* 初期段階では管理画面や大規模なジョブ管理基盤は構築しない
